Architecture

Evidence in. Bounded action. Learning out.

Request lifecycle

Sixteen explicit steps from request to next practice.

01–04

Establish context

Receive request, establish identity, load learner context, then determine intent and target skill.

05–08

Prepare execution

Determine retrieval needs, retrieve authorised evidence, select a capability and validate its input schema.

09–12

Execute safely

Apply permission and policy checks, execute the bounded MCP operation, return structured results and provenance, then generate the learner-facing response.

13–16

Close the learning loop

Present activity, record permitted attempts and signals, update learning state where permitted, and select subsequent practice.

RAG

Authorised retrieval

Resources are cleaned, chunked and metadata-enriched before retrieval and filtering. Production vector databases, embeddings and rerankers remain implementation decisions.

MCP

Capability contract

Capabilities are modelled with name, description, input/output schema, version, permissions, safety constraints and evidence requirements.

Governance boundary

Generated text does not get an implicit execution channel.

The intended boundary places schema validation, permission checks and policy enforcement between orchestration and specialised MCP operations. Production deployment additionally requires authentication, least privilege, allow-lists, auditability, credential isolation and learner-data lifecycle controls.
